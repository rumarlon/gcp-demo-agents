# Personal Assistant Agent Spec

## Overview
A personal assistant AI agent designed for general conversation, user preference tracking, and personal fact recall. The agent utilizes GCP Memory Bank to persist facts, preferences, and context across multiple user sessions.

## Architecture
- **Framework**: Google ADK (Agent Development Kit) in Python
- **Model**: `gemini-3.6-flash`
- **Memory Strategy**: GCP Memory Bank with `PreloadMemoryTool` for turn-start context injection and an `after_agent_callback` (`add_session_to_memory`) for background memory generation.
- **Scaffolding**: Prototype-first (`agents-cli scaffold create personal-assistant --agent adk --prototype`).

## Example Use Cases
1. **Fact & Preference Storage**: User states "I prefer short concise answers and I am vegetarian."
2. **Cross-Session Recall**: In a subsequent session, user asks "Suggest three lunch ideas for me", and the agent retrieves vegetarian preference and concise format requirements from Memory Bank.
3. **Personal Context Recall**: User asks "Where did I leave off on my reading list?", and the agent retrieves previously discussed context.

## Tools Required
- **`PreloadMemoryTool`**: Built-in ADK tool that queries Memory Bank and injects memories into system instructions at turn start.
- **`generate_memories_callback`**: `after_agent_callback` function calling `callback_context.add_session_to_memory()` to sync conversation turns to Memory Bank.

## Evaluation & Testing Strategy

### 1. Behavioral Evaluation (`agents-cli eval`)
- **Dataset (`tests/eval/datasets/assistant_eval_dataset.json`)**:
  - Multi-turn dialogues testing intent comprehension, tone, concise formatting, and general assistant helpfulness.
  - Multi-turn in-session memory and context usage.
- **Eval Config (`tests/eval/eval_config.yaml`)**:
  - `final_response_quality`: Assesses response helpfulness, clarity, and adherence to user request.
  - `multi_turn_task_success`: Verifies overall task completion in multi-turn interactions.
  - `multi_turn_trajectory_quality`: Evaluates logical progression and context maintenance across turns.

### 2. Cross-Session Memory Integration Tests (`pytest`)
- **Integration Test (`tests/integration/test_memory_bank.py`)**:
  - **Session 1**: Send user preference/fact (e.g., "My favorite beverage is Matcha Green Tea"). Trigger `add_session_to_memory()`.
  - **Memory Indexing Sync**: Verify memory generation in Memory Bank service.
  - **Session 2 (New Session ID)**: Create a new session for the same user ID, execute turn with `PreloadMemoryTool`, and assert that the agent retrieves and mentions the stored preference.

## Success Criteria
- **Behavioral Eval**: `final_response_quality` >= 0.85, `multi_turn_task_success` >= 0.90 via `agents-cli eval run`.
- **Memory Integration**: 100% pass rate on `pytest tests/integration/test_memory_bank.py` for multi-session memory recall.

## Assumptions
- Primary development mode: Local prototype using ADK runner, switchable between `InMemoryMemoryService` for offline dev and GCP Memory Bank when connected.
- Project name: `personal-assistant` (26 chars or less, lowercase, hyphens allowed).

## Constraints & Safety Rules
- Maintain strict data isolation across distinct user IDs.
- Do not fabricate user memories or personal history if no memory matches the query.
